# 设计与口径说明（用电监测与功率限额服务）

本服务完全本地运行，不依赖任何外部系统。本文档约定**单位、时间、预算/降载、
幂等/迟到数据、权限**五件事的确定口径，代码与测试均以本文为准。

---

## 1. 数据模型与目录

- 站点 `Site`：功率上限 `limit_w`（W）与恢复比例 `restore_ratio`。
- 回路 `Circuit`：挂在站点下，目录级限额（当前预算判定以**站点**为执行域，
  回路字段保留用于展示/后续扩展）。
- 设备 `Device`：
  - `interruptible`：是否可中断负载（只有它参与分级降载）；
  - `shed_priority`：降载优先级，**数字越小越先被关闭**，相同优先级按设备 id 稳定排序；
  - `rated_power_w`：额定功率，用于**恢复试算**时的保守估计；
  - `baseline_when_shed_w`：被切除后保留的基线功率（默认 0）。
- API Key 三级：
  - 全局 Key（`site_id = null`）：可读写所有站点；
  - 站点 Key（`device_ids` 为空）：可读写所属站点全部设备；
  - 设备 Key（`device_ids` 非空）：只能读写白名单设备，写同站点其他设备也算越权。

内置演示目录见 `power_budget/seed.py`：站点 `site-a`，上限 1000W、恢复比例 0.95，
密钥 `admin-key` / `site-a-key` / `dev-fixed-key`。

## 2. 单位口径

内部一律换算为 **SI 单位**：功率 W、电压 V、电流 A。换算在入参校验阶段完成：

| 指标 metric | 允许单位 unit | SI 系数 |
|---|---|---|
| `power` | `W`, `kW` | ×1, ×1000 |
| `voltage` | `V`, `mV` | ×1, ×0.001 |
| `current` | `A`, `mA` | ×1, ×0.001 |

- 单位不属于该指标（如给 power 传 `V`）→ `unit_metric_mismatch`；
  单位字符串无法识别 → `unknown_unit`。两者是**不同拒绝码**。
- “明显越界”在 SI 值上判定（避免用不同单位绕过）：
  - 功率 `[0, 1e7]` W；电压 `[0, 1e4]` V；电流 `[0, 1e5]` A。
  - 负数、NaN、Inf 一律拒绝（`value_out_of_range` / `non_finite`）。
- 功率取值：优先用 `power`；未提供 power 但同时提供 `voltage` 与 `current` 时，
  以 `V×A` 推导。只给电压不给电流（且无 power）→ `missing_field`。

## 3. 时间口径

- 所有时间内部统一为 **带时区的 UTC `datetime`**。
- 入参 `ts` 支持 ISO8601 字符串（末尾 `Z` 视为 UTC，无时区的朴素时间按 UTC）
  或 Unix epoch 秒（int/float，bool 不算）。无法解析 → `bad_timestamp`。
- 区分两个时刻：
  - `ts`：设备**测量时刻**（遥测发生时刻）；
  - `ingest_ts`：服务**入库时刻**（由服务时钟打戳，测试中为 FakeClock）。
- 统计窗口统一为半开区间 **`[start, end)`**：含起点、不含终点。
- 曲线分桶按 UTC 自然边界对齐：`1m` / `5m` / `1h`，跨天按 UTC 零点切桶；
  `raw` 不上采样，一个测量时刻一个点。

### 迟到与乱序数据（归属规则一致、确定）

以入库时刻 `now` 为基准：

- `age = now - ts`
- `age > late_grace_seconds`（默认 900s）→ 拒绝 `stale_late`（迟到超窗）；
- `age < -future_tolerance_seconds`（默认 5s）→ 拒绝 `stale_late`（超前过多）；
- 窗口内的迟到数据**允许**，按其**测量时刻 `ts` 归属**到正确位置
  （存储按 ts 有序插入），因此乱序不影响统计/判定结论。
- 同一设备同一测量时刻只允许一个值：
  - 完全相同（power/voltage/current 都相等）→ 幂等返回首次样本，**不重复计数**；
  - 值不同 → 拒绝 `conflicting_sample`。

## 4. 幂等约定

- 每次上报必须带字符串 `idempotency_key`（缺失 → `missing_field`）。
- 幂等键命中：无论首次结果是接受还是拒绝，都**原样重放首次结论**
  （`duplicate=true`），不会二次入库、不会“重试后反而成功”、不会重复计数。
- 拒绝结果也按幂等键固化；无幂等键的请求不固化（调用方修正后可重试）。
- “相同数据”有两层去重，互为补充：
  1. **同幂等键**：重放首次结论；
  2. **同设备 + 同测量时刻 + 同值**（即使幂等键不同）：按首次样本幂等，不重复计数。

## 5. 预算与分级降载

### 5.1 帧（采集周期）

预算以**测量时刻帧**为单位：同一 `ts` 的多台设备属于同一帧。

- **推荐用法**：网关一个采集周期成批到达，调用原子接口
  `POST /api/v1/telemetry/frame`（服务层 `ingest_frame()`）。
  一批数据在**同一把锁**内依次入库，全部入库后**只做一次预算判定**，
  同一 decision 写回该批每条结果 —— 多设备同时上报结论唯一。
- 单设备接口 `POST /api/v1/telemetry`（`ingest()`）也在锁内串行，
  但它只基于“当前测量时刻这一帧已到达的设备”判定（未到设备按本帧缺数据，
  **不拿上一帧功率冒充本帧**）。要断言精确的“齐帧结论”请用 frame 接口。

### 5.2 当前帧功率

- 判定输入只包含测量时刻**恰等于本帧 ts** 的样本。
- 已被降载设备按切除基线计（默认 0），**不采用切除前的旧功率样本**。
- 本帧缺数据的设备：功率按 0 计入求和，但在判定依据中**显式列出**
  （“本帧缺数据不计入: …”），绝不静默臆造，也不会被“空转降载”。
- 功率来源：`power` 字段优先，否则 `V×A`。

### 5.3 降载（超限）

1. 计算当前帧总功率 `frame_total`；
2. `frame_total > limit` 判为超限（**等于上限不算超**）；
3. 求“让总功率 ≤ limit 的最小目标降载集”：按 `(shed_priority, device_id)`
   依次切除**本帧有实时功率贡献**的可中断负载，直到 ≤ limit 或候选耗尽；
4. 已在降载集合中的设备不会被重复加入；同一设备在一次判定中
   不可能同时出现在 `newly_shed` 与 `restored`。
5. 若连可中断负载都切完仍超限（例如不可中断负载自身就超），
   `over_budget=true` 保留，`measured_power_w` 如实反映超限值。

### 5.4 恢复（滞回，防抖动）

当 `frame_total ≤ limit` 且存在被切负载时，按**降载的逆序**逐级尝试恢复：

- 恢复试算功率 = 当前在线功率 + 候选恢复设备的**额定功率**（保守估计，
  未知额定则按基线 0），**不使用切除前陈旧样本**；
- 只有试算功率**严格小于** `restore_threshold = limit × restore_ratio`
  才真正恢复（**等于阈值不恢复**），恢复一级后立即用新状态试算下一级。

“超限阈值 1000 / 恢复阈值 950”之间形成滞回带，负荷在阈值附近抖动时
负载不会来回开关。

### 5.5 并发一致性

所有上报路径（单条与批量）都在 `Store` 的同一把可重入锁内执行
“鉴权 → 校验 → 幂等 → 入库 → 预算判定 → 降载状态更新”，因此：

- 预算不会被并发击穿（串行化临界区）；
- 同一负载不会被重复降载（集合去重 + 一次判定一个目标集）；
- 幂等表与样本去重保证并发重复提交只计一次；
- 并发测试见 `tests/test_concurrency.py`。

## 6. 统计口径

### 6.1 功率曲线

`GET /api/v1/sites/{site}/curve?start&end&align`

- 站点曲线：同一测量时刻各设备功率求和后再分桶；
- 桶内给平均、最大、样本数；
- **没有样本的时间桶不补零、不出现在 `points` 中**，而是在 `empty_buckets`
  里显式列出（对照即可识别缺数据时段）；
- 输入先按测量时刻去重排序，重复/乱序不影响结果，重复查询结果稳定。

### 6.2 累计能耗

`GET /api/v1/devices/{id}/energy`、`/api/v1/sites/{id}/energy`

- 相邻样本做**梯形积分**：`E = Σ (P0+P1)/2 × Δt`，单位 Wh；
- 相邻样本间隔 **超过缺口阈值** `gap_seconds`（默认 300s）的区间记为**缺口**，
  缺口段**不按零积分**；
- 积分取数会额外携带窗口外紧邻的各一个样本，仅用于对窗口端点做线性插值；
  覆盖/缺口时长仍严格按窗口裁剪；
- 返回字段显式报告：
  - `energy_wh`：仅覆盖时段的累计能耗；
  - `covered_seconds` / `gap_seconds`：覆盖与缺口秒数（互补）；
  - `complete`：窗口内是否无缺口（要求至少两个有效样本）。
  - **`complete=false` 时不要把 energy_wh 当作全窗口真实总量**；
- 站点能耗 = 各设备分别积分后求和；只要有样本的设备中任一带缺口，则站点
  `complete=false`。无样本设备不臆造能耗（按设备维度查询可见其缺口）。

## 7. HTTP 接口与拒绝码

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/v1/telemetry` | 单设备上报 |
| POST | `/api/v1/telemetry/frame` | 原子批量帧上报（逐条结果，部分拒绝返回 207） |
| GET  | `/api/v1/sites/{id}/curve` | 站点功率曲线 + 空桶 |
| GET  | `/api/v1/sites/{id}/energy` | 站点累计能耗 |
| GET  | `/api/v1/devices/{id}/energy` | 设备累计能耗 |
| GET  | `/api/v1/sites/{id}/budget` | 当前降载集合与最近判定依据 |
| GET  | `/api/v1/_debug/snapshot` | 全量样本/降载/判定快照（本地调试） |

鉴权用请求头 `X-API-Key`。HTTP 状态：200 接受/幂等；401 未认证/越权；
404 站点或设备不存在；422 校验类失败；207 批量帧中存在被拒绝条目。

可区分的 `reason`：
`missing_field`、`bad_type`、`non_finite`、`unknown_metric`、`unknown_unit`、
`unit_metric_mismatch`、`value_out_of_range`、`bad_timestamp`、`unknown_device`、
`unauthorized`、`stale_late`、`conflicting_sample`。
（重复上报不是拒绝：HTTP 200 且 `duplicate=true`。）

每次判定的 `decision.basis` 是人类可读的判定依据串，逐行记录
“当前帧功率 → 降载/恢复每一步试算值 → 最终降载集合”，便于定位问题到底属于
**拒绝、降载还是统计口径**。
