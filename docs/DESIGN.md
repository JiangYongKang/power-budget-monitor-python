# 设计与口径说明

## 1. 单位口径

| 物理量 | 内部单位 | 接受的上报单位（大小写不敏感） |
|---|---|---|
| 功率 | W | `w`, `kw`, `mw`(兆瓦), `wh` |
| 电压 | V | `v`, `kv`, `mv`(毫伏) |
| 电流 | A | `a`, `ma`, `ka` |

- 上报值在通过校验后统一换算为 W / V / A 落库，之后所有预算与统计只使用归一化值。
- 单位不在白名单 → 拒绝，原因 `invalid_unit`，与字段缺失、越界明确区分。

**量程（归一化后）**：功率 `[0, 10 MW]`、电压 `[0, 100 kV]`、电流 `[0, 100 kA]`。
负值或越界 → `out_of_range`。

## 2. 时间口径

- 所有时间戳必须**带时区**（无时区 → `invalid_timestamp`），服务端统一转 UTC 存储。
- 接受迟到数据：只要 `2000-01-01 <= ts <= 当前时间 + 5 分钟` 即为合法时间。
  超过当前 5 分钟以上的“未来数据” → `invalid_timestamp`。
- 迟到/乱序数据按**自身时间戳**插入有序序列并归属到真实时间窗，
  不按到达顺序归属。同一设备相同时间戳时，以后到达的一条为“最新值”。
- 统计窗口统一为**左闭右开 `[start, end)`**，按 UTC 对齐；跨天窗口无需特殊处理，
  分桶从 `start` 起每 `bucket_seconds` 一个桶，末尾桶可能不足桶长。

## 3. 幂等约定

- 幂等键为 `(device_id, report_id)`：重复上报（同设备同 id）只入库一次，
  接口返回 `accepted=true, duplicate=true`，不再触发预算判定，不重复计数。
- 统计侧对输入点再次按 `(timestamp, report_id)` 去重，乱序/重复输入产出相同结果
  （同一批数据重复查询结论稳定）。

## 4. 校验与权限边界

上报处理顺序（拒绝原因互斥、可区分）：

1. 设备不存在 → `unknown_device`
2. token 不匹配/为空 → `unauthorized`（每台设备独立 token，恒定时间比较）
3. 字段缺失（device_id / power / power_unit / report_id / timestamp）→ `missing_field`
4. 时间戳非法 → `invalid_timestamp`
5. 单位无法识别 → `invalid_unit`
6. 数值越界 → `out_of_range`

**只有 1~6 全部通过的数据才会落库**；被拒绝的上报不影响任何预算判定与统计结果
（见 `tests/test_api_e2e.py`）。

## 5. 预算与分级降载规则

- 预算作用于 `site` 或 `circuit` 两级（可分别配置）。每次合法上报后，
  依次对设备所属站点与回路各做一次判定。
- 当前功率 = 作用域内每台设备**最新一条**遥测功率之和；已被降载的设备按 0 计。
- **超限降载**：`total > limit_w` 时，按 `shed_priority` 升序（数字小先降，
  同值按 device_id 确定性打破平局）依次关闭 `interruptible` 负载，
  每关一台从预计总功率中扣除其最新功率，直到 `total <= limit_w` 为止。
  `critical` 负载永不参与降载。判定采用严格大于：**总量恰好等于上限不动作**。
- **滞回恢复**：仅当 `total < restore_w` 时才考虑恢复；按降载的逆序逐台恢复，
  且要求恢复后预计总功率 `<= limit_w`（不会立即再次超限）。
  `restore_w < total <= limit_w` 为滞回死区，保持现状，避免阈值附近反复开关。
  必须配置 `restore_w < limit_w`，否则接口拒绝配置。
- **并发一致性**：同一作用域的判定在进程内锁中串行执行；降载集合的检查与变更、
  事件记录是同一临界区，因此不会出现重复降载同一负载、预算被击穿或恢复抖动。
  并发测试见 `tests/test_budget.py::test_concurrent_reports_budget_consistent`。

## 6. 统计口径

- **功率曲线**：桶值为桶内所有样本的平均值；**空桶返回 `avg_power_w=null`
  且 `samples=0`，绝不静默当 0**。
- **累计能耗（Wh）**：对窗口内点做梯形积分（相邻点平均功率 × 间隔小时数）。
  - 窗口内不足 2 个样本 → `energy_wh=null`（区分“没数据”与“能耗为 0”）。
  - 相邻样本间隔超过 `max_gap_seconds`（默认 3600s）的区段视为缺数据，
    **不参与积分**（不假设功率为 0 或线性外推）。
- 所有聚合前先排序、去重，迟到/乱序/重复数据不改变最终结论。

## 7. 本地验证方式

```bash
uv sync
uv run pytest -s          # -s 打印每个用例的“输入数据/判定依据/最终状态”
uv run uvicorn main:app   # 配合 README 中的 curl 手工验证
```

测试场景覆盖：

| 文件 | 场景 |
|---|---|
| `test_validation_and_auth.py` | 字段缺失、非法单位、越界、非法时间戳、迟到合法、越权、未知设备 |
| `test_ingestion_and_stats.py` | 重复 report_id、迟到/乱序归属、重复查询稳定、空桶非零、缺口不积分 |
| `test_budget.py` | 优先级分级降载、关键负载保护、临界不触发、滞回死区、恢复、并发上报一致、并发幂等 |
| `test_api_e2e.py` | 拒绝上报不影响预算/统计、HTTP 降载→幂等→恢复全流程 |

## 8. 已知范围限定

- 存储为进程内内存实现，重启不保留（满足本地复现与验证的要求，不接外部服务）。
- 鉴权为本地静态 token；并发控制为单进程锁（多进程部署不在本地演示范围内）。
